四种写法，决定项目能不能被打包搬走

场景：一个 py + data/ + config.json，整个文件夹要拷进 U 盘 / 虚拟机镜像
01 · 概念

硬编码

NAME = "覃祖悦"
print(NAME)

值直接写死在源码里。要换内容，必须打开源码改、再保存运行。

值能跑，但改不动
02 · 路径

绝对路径

open(r"E:\pythonProject\a.txt")

从盘符根目录开始的完整地址，定位唯一、一眼知道文件在哪。

换电脑 / 换盘 / 换文件夹即失效
03 · 路径

相对路径

open("data/a.txt")
open("../data/a.txt")

以当前工作目录 cwd 为起点找文件，目录结构不变就能用。

cwd 一变就找错文件
04 · 推荐

pathlib 规范写法

BASE = Path(__file__).resolve().parent
p = BASE / "data" / "a.txt"

路径由脚本自己算：不写盘符、不依赖 cwd，跨 Windows / 欧拉。

打包即用，发同学也不炸

① 看到这三样，就是硬编码

· 姓名 / 学号 / 端口 / 密钥直接写在赋值里：NAME = "覃祖悦"

· 盘符或用户目录出现在字符串里："C:\Users\…"、"E:\pythonProject"

· 同一个项目换个目录就报错——改一次内容要改一次源码

判断法：这段代码交给同学、换台电脑，还能原样跑吗？

② 绝对路径什么时候是对的

· 路径来自命令行参数：sys.argv[1]

· 路径来自环境变量或配置文件

· 路径来自用户在文件对话框里自己选的位置

外部给的就该用绝对路径；错在把它写进源码。

③ 一句话记法

· 值放 config.json，别写死在 py 里

· 路径靠 Path(__file__).resolve().parent 自己算

· 非要相对路径，先 os.chdir(BASE) 站好位置

三件事做完，拷 U 盘、打包进虚拟机镜像都能直接跑。

03相对路径：跟着 cwd 走

在脚本目录里 open("data/sample.txt") → ✔

open("data/sample.txt") → FileNotFoundError ✘

坑不在"相对"，在 cwd：快捷方式、任务计划、IDE、从别处敲 python 都会变。

结论三句话带走

1. 别把值写死，外置到 config.json
2. 别把路径写死，用 Path(__file__).parent
3. 避免裸相对路径，或先显式 os.chdir(BASE)
4. 打包 exe 再兜底：getattr(sys, "_MEIPASS", BASE)
